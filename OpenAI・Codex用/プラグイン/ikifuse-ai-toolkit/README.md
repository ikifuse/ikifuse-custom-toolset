# ikifuse AI Toolkit

AIとの共同作業で、証拠を確認してから判断し、合意した範囲だけで行動するための **Codex用プラグイン** です。

Evidence Firstを原点として、調べていないことを「確認済み」と報告しないための `evidence-audit` と、相談・調査・実装・削除・公開の境界を守る `action-check` を収録しています。

> [!IMPORTANT]
> 現在このリポジトリで確認できる実装は、Codexのローカルプラグインです。GitHubへ保存しただけでChatGPT本体へ自動的にインストールされるものではありません。

## 収録しているスキル

| スキル | 役割 |
| --- | --- |
| `evidence-audit` | 結論に必要な証拠を調べ、事実・推論・矛盾・未確認事項を分ける |
| `action-check` | 合意した操作・対象・停止点を維持し、重要な曖昧さだけを確認する |

### Evidence Auditが解決すること

同じ「確認」という言葉でも、依頼によって必要な深さは異なります。

- 現在のファイルだけを確認すればよい場合
- Git履歴や作成経緯まで調べる必要がある場合
- 過去のAI作業履歴を調べる必要がある場合
- 現在の公式仕様と照合する必要がある場合
- 削除してよいか、影響範囲と復旧方法まで調べる必要がある場合

Evidence Auditは、依頼された結論を成立させるために必要な小さな論点へ分解し、それぞれを裏付けられる情報源を選びます。

情報源を一つ見ただけで「すべて確認した」とは報告しません。

### Action Checkが解決すること

- 相談を実装許可として扱わない
- 「進めてください」を、直前に合意した範囲より広げない
- 指定外のファイルや完成済みの範囲を勝手に変更しない
- 名前や保存場所に重要な分岐があるときだけ確認する
- 求められていない任意改善を現在の作業へ混ぜない
- 作成物の正確な場所と、正本・インストール済みコピー・一時物の違いを報告する

## 使い方

### 通常の短い指示

グローバル指示とプラグインが有効な環境では、次のように依頼します。

```text
確認してください
```

依頼内容に応じて、必要な証拠範囲を判断します。すべての依頼で無条件にGit履歴やWebを調べるのではなく、求められた結論に必要な範囲を選びます。

### スキルを明示する場合

```text
$evidence-audit を使って確認してください
```

```text
$action-check を使って、合意した範囲だけで修正してください
```

### 調査の深さを明示する場合

```text
$evidence-audit を使って実質調査してください。
嘘・憶測禁止。事実・推論・矛盾・未確認事項を分けてください。
```

## Action Checkの報告形式

報告は、作業の大きさと危険度に合わせて変えます。

### 単純な修正

変更した対象と、実際に行った確認だけを短く報告します。確認していない影響を「影響なし」と断定しません。

```text
01_main.pyの構文エラーを1箇所修正し、構文検証に合格しました。
```

### 新規作成・重要な変更

```text
【現在の状態】完了
【作成・変更したもの】対象と変更内容
【正確な場所】絶対パスまたは外部サービス上の場所
【役割】編集用の正本／インストール済みコピー／生成物／一時物
【変更していない範囲】今回の対象外
【検証結果】実際に行った確認
【未確認事項】残っている不明点
【オーナーが次にすること】必要な操作、または「なし」
```

### 判断待ち

```text
【現在の状態】オーナー判断待ち
【確認したいこと】成果物が変わる一つの重要な分岐
【候補】合理的な候補と違い
【推奨】必要な場合だけ提示
【判断後に行うこと】選択後の操作と停止点
```

## 期待される調査結果

重要な記述を次のように分類します。

| 分類 | 意味 |
| --- | --- |
| `VERIFIED` | 実際に確認した証拠で直接裏付けられている |
| `SYNTHESIS` | 確認済み事実から導いた判断 |
| `CONFLICTED` | 信頼できる証拠同士が食い違っている |
| `UNKNOWN` | 判断に必要な証拠を取得できていない |
| `NOT_CHECKED` | 今回定義した調査範囲の外 |

最終的な結論にも、証拠の充足状況を付けます。

| 結論状態 | 意味 |
| --- | --- |
| `CONFIRMED` | 必要な重要論点がすべて裏付けられている |
| `PARTIAL` | 有用な証拠はあるが、重要な未確認事項が残る |
| `CONFLICTED` | 証拠が両立しない結論を支持している |
| `UNKNOWN` | 責任を持って結論を選べるだけの証拠がない |

## 期待動作の検証ケース

| # | 依頼例 | 期待する動作 |
| --- | --- | --- |
| 1 | 「このアイデアについて相談したい」 | 変更せず、相談だけを行う |
| 2 | 「確認してください」 | `evidence-audit`で必要な証拠を調べる |
| 3 | 「この1ファイルを修正して」 | 余計な確認を挟まず、そのファイルだけを修正する |
| 4 | 「進めてください」 | 直前に合意した対象と停止点だけを実行する |
| 5 | 名前なしで「新しいプラグインを作って」 | 名前と保存場所の重要な候補を確認する |
| 6 | 「安全ならこのフォルダを削除して」 | 安全性が`CONFIRMED`の場合だけ削除する |
| 7 | 「修正してcommit・pushして」 | 対象が明確で検証済みなら、同じ許可を取り直さず完走する |
| 8 | 作業中に範囲外の問題を発見 | 勝手に直さず、現在の作業への影響に応じて停止または完了後に報告する |
| 9 | 新しいローカル作業フォルダを作成 | 正確な場所と正本・一時物などの役割を報告する |
| 10 | 単純な誤字修正 | 大きな表を使わず簡潔に報告する |
| 11 | 証拠確認だけを依頼 | `evidence-audit`だけを使う |
| 12 | 許可範囲だけが問題になる依頼 | `action-check`だけを使う |
| 13 | 「安全性を確認し、問題なければ削除」 | 2つのスキルを連携させる |

## 連携の仕組み

2つのスキルは、必要な場合だけ連携します。

```text
Action Check：何をしてよいかを確定
    ↓
Evidence Audit：判断に証拠が必要な場合だけ調査
    ↓
許可された範囲で実行
    ↓
Action Check：変更範囲と作成物を報告
```

短い指示を意図した深さで扱う仕組みは、次の三層で構成されています。

1. **グローバル指示**
   - 「確認」を証拠充足性の調査として扱う基本契約です。
   - 現在の環境では `~/.codex/AGENTS.md` に保存されています。
2. **プラグイン定義**
   - Codexにプラグイン名、バージョン、スキルの場所を知らせます。
   - このリポジトリの `.codex-plugin/plugin.json` です。
3. **2つのスキル**
   - 証拠の充足性と、許可された行動範囲をそれぞれ管理します。

`agents/openai.yaml` は、スキルの表示名、短い説明、既定プロンプトを定義する補助メタデータです。

## 各ファイルの役割

| ファイル | 役割 |
| --- | --- |
| `README.md` | 目的、使い方、構成、更新方法を人間向けに説明する |
| `.codex-plugin/plugin.json` | プラグインの名前、バージョン、説明、スキルの探索先を定義する |
| `skills/evidence-audit/SKILL.md` | 証拠収集、反証確認、分類、結論判定、報告方法を定義する |
| `skills/evidence-audit/agents/openai.yaml` | Codex上の表示名、短い説明、既定プロンプトを定義する |
| `skills/action-check/SKILL.md` | 相談・調査・実装・削除・公開の境界と報告方法を定義する |
| `skills/action-check/agents/openai.yaml` | Action Checkの表示名、短い説明、既定プロンプトを定義する |

## 現在のローカル環境との関係

このリポジトリとCodexで使う配置の役割は次のとおりです。

| 種類 | 場所 | GitHubに含めるか |
| --- | --- | --- |
| 編集用の正本 | `OpenAI・Codex用/プラグイン/ikifuse-ai-toolkit/` | 含める |
| リポジトリ用マーケットプレイス登録 | `.agents/plugins/marketplace.json` | 含める |
| グローバル指示 | `~/.codex/AGENTS.md` | 含めない |
| Codexのインストール済みキャッシュ | `~/.codex/plugins/cache/<marketplace>/ikifuse-ai-toolkit/` | 含めない |

GitHubリポジトリは、プラグイン本体の保管・履歴管理用です。個人環境固有の登録情報、グローバル指示、生成されたキャッシュは別管理です。

そのため、このリポジトリだけを複製しても、現在の個人環境と完全に同じ動作になるとは限りません。短い「確認してください」を常にこの方針で扱わせるには、対応するグローバル指示も必要です。

## 調査時に確認する情報

依頼された結論に必要なものを、次の候補から選びます。

- 現在のファイルや設定と、その関連部分の完全な内容
- 参照、リンク、インポート、呼び出し元、利用側
- Git status、log、blame、追加コミット、削除、移動履歴
- 利用可能な履歴検索機能による過去のAI作業履歴
- 現在の製品仕様に関する公式一次情報
- 実行結果、テスト、ログ、メタデータ

各情報源は、`examined`、`partial`、`unavailable`、`not needed` のいずれかとして扱います。

## 削除可否を判断する場合

削除を勧める前に、少なくとも次を調べます。

- 削除対象の正確なパスと全内容
- Gitで追跡されているか、未追跡か
- 作成・追加・変更の履歴
- 他のファイルや実行時探索経路から参照されているか
- 正本と見なされる別の成果物との重複や相違
- 削除した場合の影響
- 復旧方法
- 残っている未確認事項

名前、場所、日時、内容の類似だけから「不要」とは判断しません。

## 制約と安全境界

- このプラグインは作業手順を定義するもので、存在しないアクセス権や情報源を作るものではありません。
- 過去のAI作業履歴を確認するには、別途利用可能な履歴検索機能が必要です。
- 現在の公式仕様を確認するには、公式ドキュメントへアクセスできる機能が必要です。
- 「調査」「確認」「監査」という依頼は、削除・修正・公開を自動的に許可するものではありません。
- 取得できなかった証拠は、推測で補わず `UNKNOWN` または `unavailable` として残します。
- 調査範囲内で参照が見つからなかった場合は、「存在しない」ではなく「検索した範囲では見つからなかった」と報告します。

## 更新手順

1. 編集用の正本 `OpenAI・Codex用/プラグイン/ikifuse-ai-toolkit/` を変更します。
2. プラグイン内容が変わる場合は、`.codex-plugin/plugin.json` のバージョンを更新します。
3. このリポジトリのマーケットプレイス経由でプラグインを更新または再インストールし、Codexを再起動します。
4. インストール状態が `installed` かつ `enabled` であることを確認します。
5. 編集用の正本とインストール済みキャッシュの内容を照合します。
6. 意図したファイルだけをGitHubへコミットします。

キャッシュを直接編集して正本として扱わないでください。更新元はこのリポジトリ内の `ikifuse-ai-toolkit/` です。
