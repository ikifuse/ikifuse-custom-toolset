# ikifuse Custom Toolset

AI協働開発で繰り返し使うプラグイン、スキル、ルーティン、テンプレート、判断基準などを、一か所にまとめて管理する個人用ツールセットです。

困り事ごとに道具を小さく独立させ、必要なものだけをプロジェクトへ導入できる形を目指しています。GitHub上で全体を一覧でき、新しいプロジェクトでも再利用でき、将来は役に立ったものだけを他の人へ渡せる構成にします。

## このツールセットで実現したいこと

- 困り事ごとに小さな道具を追加できる
- 必要なものだけを個別に導入・有効化できる
- 不要なものを個別に無効化・取り外しできる
- 一つを修正しても、他の道具へ影響しにくくする
- GitHubで全体の構成と中身を一覧できる
- 新しいプロジェクトでも同じ道具を再利用できる
- 外部で見つけた道具を、出所を残して保管できる
- 将来、役に立ったものだけを他の人やチームへ渡せる

## 最初に知っておくこと

このリポジトリは、道具を保管・整理するための置き場所です。

- GitHubへ保存しただけでは、CodexやAntigravityへ自動的にインストールされません。
- 導入方法、使い方、更新方法、取り外し方は、各道具のREADMEを確認します。
- このリポジトリを更新しても、すでにインストール済みのコピーへ自動反映されるとは限りません。
- リポジトリ内のフォルダを削除しても、アプリ側へインストール済みのものが自動的に削除されるとは限りません。
- 対応するAI環境や必要な設定は、道具ごとに異なります。

## 道具の種類

このリポジトリでは、次の意味で分類します。

| 種類 | このリポジトリでの意味 |
|---|---|
| プラグイン | 特定のAI環境へまとめて導入できるパッケージ。スキルや設定などを内包できる |
| 単体スキル | 特定の判断や作業手順をAIへ追加する、小さく独立した指示 |
| ルーティン | 繰り返し行う一連の作業手順 |
| ワークフロー | 特定の環境や目的に合わせた、開始から完了までの作業の流れ |
| テンプレート | 毎回同じ形で使う入力文、報告書、設計書などのひな型 |
| 判断基準 | 迷ったときに、何を根拠として判断するかをまとめた基準 |
| 過去の事例 | 問題、調査、判断、結果を後から再利用できる形で残した記録 |
| 専用の設定 | CodexやAntigravityなど、特定の環境だけで使う設定 |

一つのプラグインの中に、複数のスキルや設定が含まれることがあります。たとえばEvidence Firstは一つのプラグインで、その中に `evidence-audit` スキルが入っています。

## 基本的な使い方

1. 「現在入っているもの」または分類フォルダから、使いたい道具を探します。
2. その道具のREADMEで、対象環境、役割、導入方法、使い方、制約を確認します。
3. 必要な道具だけを対象のAI環境へ導入します。
4. 更新や取り外しを行うときも、その道具のREADMEに記載された手順を使います。

道具は一つずつ独立したフォルダに置くため、プラグインを増やす場合は次のように横へ追加できます。

```text
OpenAI・Codex用/
└── プラグイン/
    ├── evidence-first/
    ├── 次のプラグイン/
    └── さらに別のプラグイン/
```

## 新しい道具を追加するとき

- 一つの道具につき、一つの独立したフォルダを使います。
- その道具のREADMEを用意します。
- READMEには、目的、対象環境、使い方、導入方法、更新方法、取り外し方、制約を書きます。
- プラグインやスキルの機械的な識別名は、動作互換性を優先して必要に応じて英数字とハイフンを使います。
- 人が見る分類フォルダは、日本語で統一します。
- 外部から導入したものは、取り込み元、ライセンス、原形からの変更点を記録します。
- Codex用プラグインを追加した場合は、必要に応じて `.agents/plugins/marketplace.json` に登録します。
- 既存の道具と役割や保存場所が重複していないか確認します。

## READMEとIssueの役割

このREADMEには、現在確定している構成、収録済みの道具、使い方、管理方法を記載します。

Issueには、次のような内容を分けて記録します。

- 道具が必要になった背景
- 解決したい困り事
- まだ決まっていない名称や形式
- 相談中の仕様
- 次に検討したいこと

これにより、初めてリポジトリを見る人はREADMEから現在の状態を把握でき、詳しい経緯や未決定の相談はIssueで追えるようにします。

- [Issues一覧](https://github.com/ikifuse/ikifuse-custom-toolset/issues)
- [Issue #1：AIとの認識差が大きな修正コストへ進む前に止める仕組みを検討する](https://github.com/ikifuse/ikifuse-custom-toolset/issues/1)

## 技術用ファイル

### `.agents/plugins/marketplace.json`

Codexへ、このリポジトリに含まれるプラグインの名前、保存場所、利用可能状態などを伝えるマーケットプレイス定義です。

このファイルへ登録されていることと、Codexへ実際にインストール済みであることは別です。

### `.codex-plugin/plugin.json`

各Codex用プラグインの中に置く、そのプラグイン自身の定義ファイルです。

Evidence Firstでは、次の場所にあります。

```text
OpenAI・Codex用/プラグイン/evidence-first/.codex-plugin/plugin.json
```

## よくある質問

### プラグインは一つしか置けませんか？

いいえ。プラグインフォルダの中へ、一つのプラグインにつき一つのフォルダを追加できます。

### 不要な道具は削除できますか？

できます。ただし、リポジトリから削除することと、Codexなどへインストール済みの道具を無効化・アンインストールすることは別の操作です。先に利用中の場所と影響を確認し、各道具の取り外し手順に従います。

### 他の人が作ったスキルやプラグインも置けますか？

置けます。「外部から導入したもの」へ分類し、取り込み元、ライセンス、変更の有無を記録します。再配布できるかどうかは、元のライセンスに従います。

### GitHubへ置けば、すぐCodexで使えますか？

いいえ。GitHubは保管場所です。実際に使うには、対象環境への導入または有効化が必要です。具体的な手順は各道具のREADMEを確認します。

### すべてのAI環境で同じ道具を使えますか？

必ずしも使えません。共通化できる内容もありますが、プラグイン形式、スキルの配置、設定方法はAI環境ごとに異なります。
